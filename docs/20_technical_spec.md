# 技術仕様

ゲームエンジン側（Vite + PixiJS 8）で問題なく使えるアセット形式を定義する。
`src/render/sprites.ts` の実装と整合させる。

---

## 1. ファイル形式

| 項目 | 仕様 |
|---|---|
| 形式 | PNG（RGBA、8bit/channel） |
| 色空間 | sRGB |
| 圧縮 | 標準 PNG 圧縮（lossless） |
| EXIF/メタデータ | 不要、あっても無視される |

---

## 2. 背景処理

**最優先要件：完全透過 PNG（alpha channel）**

### 2.1 理想形（納品物）

- キャラクターのシルエット以外は **完全透過（alpha = 0）**
- ground shadow / drop shadow は **焼き込まない**（ゲーム内で procedural 描画）
- 背景に薄いグラデーション・テクスチャ禁止

### 2.2 フォールバック（AI で透過 PNG が出せない場合）

やむを得ず白背景 PNG で納品する場合：

| 要件 | 仕様 |
|---|---|
| 背景色 | 完全な純白 `#FFFFFF`（RGB 全 255） |
| 影 | **焼き込み禁止**（影があると flood-fill で抜けず残る） |
| アンチエイリアス | キャラ輪郭のアンチエイリアスは OK |

`src/render/sprites.ts` の `removeBackgroundFloodFill` が 4 隅から flood-fill で
RGB 全 240 以上のピクセルを alpha=0 にする。**影は 240 未満なので残る**。

### 2.3 NG 例

- 白背景 + 薄いグレー地面影 → 影が残る
- 白背景 + 放射グラデーション → 中心付近は flood-fill で抜けない
- 黒背景 / カラー背景 → sprites.ts が対応してない

## 3. 解像度とフレーミング

### 3.1 キャンバスサイズ

| 用途 | 推奨 |
|---|---|
| 納品時 | **1024 × 1024 px**（正方形） |
| ゲーム内表示 | スケール可変（実表示は 48-80px 程度） |

将来 Retina 対応や高解像度化に備えて 1024 で納品。

### 3.2 キャラクターフレーミング

| 項目 | 仕様 |
|---|---|
| キャラ全身高 | キャンバス高の **70% ± 3%**（約 720px） |
| 水平位置 | キャンバス中央 |
| 足元基準ライン | キャンバス底から **15%** の位置 |
| 上下マージン | 上約 15% / 下約 15% |
| 左右マージン | キャラ輪郭から最低 10% |

### 3.3 ポーズ間の一貫性

- **全ポーズで体幹中心が同じ位置** に来ること
- **全ポーズで足元基準ラインが同じ Y 座標** にあること（`splat` 等の横向きは例外）
- スケール（体の大きさ）は全ポーズで統一

これが揃わないと、ゲーム内で state 切替時にキャラが跳ねる。

## 4. ファイル命名規則

### 4.1 基本ルール

```
NN_poseName.png
```

- `NN`: 2 桁 zero-pad の番号（`01`-`99`）
- `poseName`: 英小文字 + アンダースコア
- 拡張子: `.png` 固定

### 5.4 色の使い方

- 彩度は **全体的に低め**（storybook 避けつつも鮮やかすぎない）
- グラデーションは **最小限**（cel shade 寄り）
- 原色（純赤・純青等）は禁止（ただしフラナの赤目・赤首輪は赤系統の中〜濃度で OK）

## 6. 納品フォーマット整合

### 6.1 1 発注 = 1 ポーズ = 1 ファイル

- grid 納品禁止（4-pose-in-one は不可）
- 複数ポーズ発注時も **個別ファイル**で納品
- AI が 1 画像内にまとめて出す場合は **クロップして分割保存**

### 6.2 禁止事項

- ファイル内にテキストラベル焼き込み（"walk", "run" 等）
- フレーム・境界線
- 透かし・署名
