# M2.1 Direction Reset

この文書は Σ-8 実装後に決め直した、M2.1 以降の設計方針の正本。
コード実装は `CLAUDE.md` とこの文書を先に読み、旧要素を増やさない。

## 大方針

くそざこ村は、旧来の「くそざこポイントで施設を買い、ランダム死因を増やす idle 観察ゲー」から、
**低解像度スタイライズド地形で村を作る箱庭開発ゲーム**へ寄せる。

優先する体験:

- 地形を盛る、削る、坂道化することで移動ルートが変わる
- 水位、雨、泥、雪、崖、段差が画面で読める
- 建物は map 上に置かれ、資源とちびわふ労働で完成する
- ちびわふは異常に弱いが、事故の原因は画面上の環境から理解できる
- フラナだけはちびわふより少しまともに動ける

## 採用する変更

| 項目 | 方針 |
|---|---|
| 建設 | `points` 消費の旧 `BUILDINGS` を廃止し、map 上 feature/building + 資源 + 労働へ統一 |
| points | スコア、図鑑、村ランク、解放条件として残す。建設費には使わない |
| 旧建物 | 産屋 / やぐら / 墓地 / 農業区 / 火事場は廃止または新建物へ吸収 |
| くそざこ音頭 | 廃止。画面上の建物/天気/食料/地形に由来するイベントへ置換 |
| NPC | スズ / ココン / ルーは廃止。フラナを唯一の主要 NPC にする |
| フラナ移動 | ちびわふより段差に強いが、万能ではない |
| カメラ | 自由回転ではなく、角度プリセットを追加 |
| 見た目 | 海表示、段差スケール、props、建物表現を優先強化 |
| キャラ画像 | ドット絵化は別途モックで判断。Claude は勝手に差し替えない |

## 建設統一方針

現状は 2 系統が混在している。

- 旧: `src/city/buildings.ts` の `BUILDINGS` を `points` で購入
- 新: `src/main.ts` の `BuildKind` を資源で配置し、`Feature.devLevel` / `workSec` で建設

M2.1 では新方式へ統一する。

### 旧建物の吸収先

| 旧要素 | 新方式での吸収先 |
|---|---|
| 農業区 | `farm` / `pasture` / 将来の `granary` |
| 火事場 / 鍛冶場 | `kiln` / 将来の `forge` |
| 墓地 | 将来の `memorial` / `graveyard` feature。points multiplier ではなく士気/記録用途 |
| わふ太鼓やぐら | 廃止。必要なら祭り用 `meeting_square` に置換 |
| 産屋 | `house` / 将来の `nursery` に吸収 |

### migration 方針

- 既存 save の `buildings` は即削除しない
- ロード時 migration で近い `Feature` に変換できるものは変換する
- 変換不能なものは legacy 表示だけ残し、新規建設 UI からは消す
- `points` は減らさず、スコア/村ランク用途へ残す

## くそざこ音頭廃止

音頭は旧 idle 死亡イベントとしては機能していたが、地形開発ゲームの因果と噛み合いにくい。
M2.1 では次へ置き換える。

- 食料不足によるパニック
- 嵐、雪、熱波など天気由来のリスク
- 建物の過密、火災、停電、崩落など画面上に原因がある事故
- 将来の広場/集会イベント。ただし死亡原因は環境から読めること

既存 death dex の `ondo` は legacy 扱いでよい。新規発火は止める。

## NPC 整理

### 廃止

- スズ: 点呼、死亡反応、ママ呼び、数える UI 的役割
- ココン: いじめ、棒、ボコ参戦
- ルー: 無口 NPC

これらの役割は次へ移す。

| 旧役割 | 移管先 |
|---|---|
| 点呼 / 数える | HUD / event log |
| いじめ / ボコ | ちびわふ同士の trait 反応 |
| 死亡反応 | フラナ / 近くのちびわふ / event log |
| 無口枠 | `mukuchi` trait |

### フラナ

フラナは残す。役割は「村の象徴、親、拠点、少しまともな移動者」。

移動ルール案:

| 条件 | ちびわふ | フラナ |
|---|---|---|
| 同高度 | 可 | 可 |
| 1 段差 + ramp | 可 | 可 |
| 1 段差 + ramp なし | 不可または事故 | 可、cost 高め |
| 2 段差以上 | 不可 | 不可 |
| waterLevel >= 0.35 | 原則不可 | 原則不可、低確率で救助行動を検討 |

フラナを万能化すると地形開発の意味が壊れるため、「ちびわふよりマシ」に留める。

## カメラ / 見た目

### カメラ角度プリセット

自由回転は採用しない。Y 軸ビルボード、クリック判定、UI 同期の前提が崩れるため。

代わりに 3 プリセットを追加する。

| Preset | 目的 |
|---|---|
| 低め | 建物/崖/滝の迫力確認 |
| 標準 | 通常プレイ |
| 真上寄り | 地形編集、通行、道作り |

### 海表示の修正

現状の問題:

- 最遠景でカメラ表示範囲がワールド外へ出る
- 全面 sea plane がワールド全体に敷かれている
- `isSea` タイルの地形面は sand atlas として描画される
- 透明海面越しに砂地が見えて、画面下が縞状に破綻する

修正方針:

- 短期: `CAMERA_MIN_SCALE` を上げ、ワールド外が見えにくいよう clamp を調整
- 本命: `isSea` タイルだけ水面 InstancedMesh にする
- 海タイル地形面は描かない、または暗い海底専用 material にする

### 高さスケール

現状は `ELEV_STEP=25` と `ELEV_SCALE=6` により、1 段が Three.js 上 150px。
ちびわふの見た目高さ 64px に対して大きすぎる。

候補:

| 案 | 内容 | 評価 |
|---|---|---|
| 短期 | `ELEV_STEP=25` 維持、`ELEV_SCALE=3-4` | save 影響が小さい |
| 本命 | `ELEV_STEP=8-12` へ細分化、`ELEV_SCALE=4` 前後 | 見た目は良いが migration / A* / generator 調整が必要 |

商業見た目重視なら本命案。ただし先に小さな検証 branch で試す。

## キャラ画像 / ドット絵判断

キャラを完全ドット絵にする可能性はある。ただし地形、UI、props と一体で判断する。

禁止:

- Claude が実装中に勝手にキャラ PNG を差し替える
- ちびわふだけドット、地形は水彩寄りのまま、という混在を本採用する

判断手順:

1. ちびわふ 1 体、フラナ 1 体、地形 1 画面のモックを作る
2. 既存水彩ビルボード版と並べる
3. 小さな表示で表情、状態、視認性を比較する
4. 採用ならアセット仕様書を更新してから生成に入る
